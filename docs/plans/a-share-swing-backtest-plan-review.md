- 评审日期：2026-10-26

## 0. 总体结论

把「可行性」拆成三层，答案不同：

| 层面 | 判断 | 关键依据 |
|---|---|---|
| 工程实现 | 可行，但风险高于方案自述（非「中等」） | 单人熟练 3–4.5 个月；约 1/3 工作量在规则边界 |
| 数据可得 | 取决于是否付费；免费只能做「近似」 | 历史 ST/停牌/涨跌停价/行业成员 |
| 策略有效 | 未知，且当前设计在合理时间内给不出可信答案 | 验收指标与样本量不匹配，alpha 未定义 |

方案作为**研究规范**的质量明显高于多数散户/小团队方案，以下原则覆盖到位，实施中不应被砍掉：

1. 历史股票池（§1.2、§3.2）——避免存活偏差的意识；
2. 无未来函数 + 信号时间与执行时间分离（§1.2、§4.6、§7.1）；
3. 成交可行性优先于收益（§1.2、§4.6、§7.3）；
4. 成本三档压力测试（§7.5）；
5. 时间顺序切分 + 滚动前推 + 拼接净值曲线（§9.1、§10.3）；
6. 多重检验意识（§14.3）；
7. 对自身结论的克制（§15 写明「研究参考门槛」，§22 写明「完成开发不等于策略有效」）。

主要问题是：**大量条目写的是「要求」，不是「可执行规则」**。标注 P0 的缺口不是可选项，而是不写清就一定跑出失真结果。

**一句话判断**：方案可以实施，但现状是「一份写得好的科研规范 + 一批没有落地的执行规则」。最大风险不是技术难度，而是花 3–4 个月、按现有门槛得到一个统计上既无法确认有效、也无法确认无效的答案。

## 1. P0：六处会导致回测失真的规则缺口

| # | 缺口 | 直接后果 |
|---|---|---|
| 1 | 无成交量参与率/容量约束 | 一字板、小盘股成交假设失真；容量无法评估 |
| 2 | 涨跌停「封死」判定未落地 | 买不进/卖不出的差一天直接改变净值 |
| 3 | 复权序列 ↔ 真实成交价无换算式 | 止损阈值被除权误触发；分红收益重复或漏计 |
| 4 | 收盘价退出与买入规则不对称 | §4.6 禁止收盘价买入，§4.7 的均线退出却隐含收盘价成交 |
| 5 | T+1 与资金时序未定义 | 同日买入卖出、开盘竞价能否使用卖出资金 |
| 6 | 停牌期间净值口径未定（P1） | 净值虚高/虚低 |

### 1.1 容量约束（缺量化）

方案 §3.2 只写「排除不符合预先规定流动性条件的股票」，§8 只写「现金不足」「整手限制」。缺三样东西：

- 单笔委托 ≤ 当日成交额/成交量的固定比例（建议 1%–5%，按回测期分档）；
- 账户规模（AUM）——没有 AUM，无法判断容量是 P0 还是 P2；
- 清仓天数估算（持仓股在跌停/停牌情景下需要几个交易日退出）。

### 1.2 涨跌停与「封死」的判据

方案 §7.3 列出了情形，但没有给判据。日线数据下只能用保守近似，且必须写死：

| 场景 | 日线可判据 |
|---|---|
| 一字涨停（买不到） | `open = high = low = close = 涨停价` |
| 开盘即涨停 | `open = 涨停价` → 视为当日开盘无法买入 |
| 一字跌停（卖不出） | `high = low = close = 跌停价` |
| 收盘跌停（不代表全天封死） | 不可作为「卖不出」依据 |

**常见错误**：「收盘价 = 跌停价 且 最低价 = 跌停价」不能判定卖不出。只要 `high > 跌停价`，盘中就曾在跌停价上方成交，止损价在跌停价之上时完全可能已成交。把它当作「全天封死」会系统性低估止损成交率、高估回撤。

另一处细节：涨跌停价必须用 `Decimal` + `ROUND_HALF_UP` 取到 0.01 元（不用 Python 默认 `round()` 的银行家舍入），除权日以除权参考价为基准。

### 1.3 复权三口径的换算（原则有，实现无）

方案 §3.1-C 已明确要求区分「信号计算价格 / 实际成交价格 / 组合持仓调整」，方向正确。缺的是换算规则：

- **信号**：后复权，或统一用复权因子序列。**不能用前复权**——前复权锚定当前价，历史值会随未来除权变动，等于引入未来信息。
- **成交**：不复权真实价。止损/止盈阈值在复权序列上计算，再换算回真实价（除权日必须重算）。
- **持仓**：送股/转增改股数；现金分红单独入账。

**必须警惕的口径冲突**：

| 数据源 | 复权口径 | 直接用它算收益的后果 |
|---|---|---|
| TuShare `pro_bar` | 分红再投 | 已隐含分红再投资，另记现金分红会**重复计算** |
| BaoStock | 涨跌幅复权法，**不参加分配** | 会**漏掉**现金分红 |
| AkShare（东财 qfq/hfq） | 算法未披露 | 需先校准再使用 |

因此「复权序列算信号 + 不复权价算成交 + 单独记分红」这套组合，只有在明确复权因子是否含分红之后才成立。建议在数据层加一条断言：相邻除权日的复权因子跳变必须能被该股的分红送转方案解释。

### 1.4 T+1 与资金时序

方案 §7.1 的顺序是：开盘前现金 → 公司行为 → 风险退出 → 卖出 → 买入。需要补两条显式约束：

- 同日买入的股票当日不可卖出（T+1 可卖数量）；
- 当日卖出资金能否用于**同一开盘竞价**的买入，取决于券商预检查。回测应默认「不可用」（保守），并在报告中注明该假设。

### 1.5 停牌定价（P1）

停牌日无收盘价，方案未定估值口径。建议：用最后可得收盘价，且不得对停牌股计当日收益；复牌首日按真实跳空结算。「停牌期间冻结资金」已在 §8 提及，与此配套。

## 2. 必须按日期分段的制度规则

方案 §7.3 要求「不同板块、不同历史时期的涨跌幅限制」，§7.5 要求「税费按回测日期的实际规则」，但都没有给表。下表可直接落地为配置：

| 规则 | 分段 |
|---|---|
| 主板 ST/*ST 涨跌幅 | 5% → **10%**，2026-07-06 起 |
| 创业板 | 10% → 20%，2020-08-24 起（ST 亦 20%） |
| 科创板 | 20%，2019-07-22 起 |
| 北交所 | 30%，2021-11-15 起 |
| 主板新股首日 | 核准制：有效申报 +44%/−36%（**不是无限制**）；2023-04-10 起注册制前 5 日不设限 |
| 创业板/科创板新股 | 前 5 日不设限 |
| 退市整理期 | 15 个交易日；首日不设限，其后主板 10%、双创 20% |
| 印花税（卖出） | 0.1% → **0.05%**，2023-08-28 起 |
| 过户费 | 沪深统一 0.001% 双向，2022-04-29 起 |
| 经手费（沪深） | 0.00487% → 0.00341%，2023-08-28 起 |
| 盘后固定价格交易 | 科创板/创业板 → **全部 A 股**，2026-07-06 起（北交所暂不） |

两条特别提示：

- **2026-07-06 的 ST 涨跌幅调整已实施**。方案未给分段表，隐含按单一比例处理；2016–2026 的回测跨越这个断点，必须分段。同日实施的「盘后固定价格交易扩围」直接推翻方案 §4.6 的一个前提，见第 3 节。
- 若回测区间覆盖 2026-07-06 之后，样本外期与开发集存在**制度断点**，应单列统计，不与前期结果合并解释。

## 3. 被忽略的新选项：收盘价成交不再是禁区

方案 §4.6：「不得使用 T 日收盘价成交，除非另行开发和验证真实可执行的收盘竞价交易模型。」

2026-07-06 起，盘后固定价格交易由科创板/创业板扩展至全部 A 股：每交易日 15:05–15:30，以当日收盘价为成交价，时间优先连续撮合。

- **意义**：T 日收盘价成交在机制上成为可执行路径，可作为独立实验组与「T+1 开盘买入」对照；
- **限制**：该时段实际成交笔数与数量很小、时间优先，**容量极低**。小资金可作补充，不能作为主成交假设；
- **影响**：若纳入，隔夜跳空的归属会被重新分配，可能显著改变策略结果，也可能只是把一个有效策略变成不可扩容的样本。

建议在 §4.6 增加：主规则仍为 T+1 开盘；新增「收盘价成交」实验组，并在报告中单列其成交率与容量估计。

## 4. 成本：缺一个日期化费率表 + 敏感性区间

### 4.1 单轮成本的量级

按当前费率、佣金万 2.5、滑点单边 0.1%、单笔 ≥2 万元估算：

| 情形 | 每轮双边 | 7 日持仓年化 |
|---|---|---|
| 当前费率 | 0.313% | 11.0% |
| 2016–2023 口径（印花税 0.1%） | 0.363% | 12.7% |
| 滑点单边 0.2% | 0.513% | 18.3% |
| 单笔 <2 万元（5 元最低佣金） | +0.05% | +1.8% |

拆解（当前口径）：买入 = 佣金 0.025% + 过户费 0.001% + 经手费 0.00341% + 证管费 0.002% + 滑点 0.1% = 0.131%；卖出再加印花税 0.05% = 0.181%。

### 4.2 成本倒推：每笔需要多少毛收益

| 目标净年化 | 5 日持仓(50 轮) | 7 日(36 轮) | 10 日(25 轮) |
|---|---|---|---|
| 净 10% | 毛 0.51%/笔 | 0.59% | 0.71% |
| 净 20% | 毛 0.71%/笔 | 0.87% | 1.11% |

**这套系统要证明自己有价值，信号必须在每笔交易上提供约 0.6%–0.9% 的毛超额收益。** 这个数字应在写第一行代码之前先估出来，它就是整个项目的 go/no-go 线。

### 4.3 方案需要补的三项

1. **日期化费率表**：佣金（含 5 元最低）、印花税、过户费、经手费、证管费，各自带生效日期区间；
2. **AUM 与最低佣金的关系**：万 2.5 下需单笔 ≥2 万元才不被 5 元最低佣金抬高成本；5 仓则资金 ≥10 万元；
3. **滑点按价格档位**：A 股最小变动 0.01 元，10 元股 1 tick ≈ 0.1%，5 元股 ≈ 0.2%，20 元股 ≈ 0.05%。统一用 0.1% 会在低价股上低估、高价股上高估。

## 5. 统计功效：方案最实质的方法论问题

需要说准确：方案 §10.3 已要求「把所有测试区间按时间顺序拼接成一条样本外净值曲线」，所以不是没做拼接。真正的缺口是两点：**验收表未说明夏普/PF 按单窗口还是按拼接后计算**，以及**没有功效分析**。即便 §15 的措辞是「研究参考门槛」，这些门槛在双向都失效。

### 5.1 单窗口能判断什么

| 窗口 | 年化夏普 0.8 对应的 t 值 |
|---|---|
| 6 个月（120 日） | 0.55 |
| 1 年 | 0.80 |
| 期望 t = 2（约 50% 功效） | 6.2 年 |
| 80% 功效 | 约 12 年 |

结论：**6 个月窗口无法区分「真实夏普 0.8」与「无边际」**，只能用于发现执行异常与灾难性亏损。

### 5.2 「2/3 窗口为正」双向失效

| 窗口数 | 无边际时误通过率 | 真实夏普 0.8 时误杀率 |
|---|---|---|
| 6 个 | 34.4% | 23% |
| 8 个 | 14.5% | 41% |

一个既拦不住无效策略、又会杀掉有效策略的门槛，不应作为验收依据。

### 5.3 PF > 1.2 的样本要求

单笔收益信噪比约 0.09（PF 1.2、胜率 50%、盈亏比 1.2）时，t ≈ 2 需要约 **400–500 笔**；考虑盈亏比分布，区间为 400–900 笔。

注意：模拟实盘 8–12 周在 7 日持仓下只有约 **40–60 笔**，只能验证成交率、滑点与信号数量，不能验证胜率或期望。

### 5.4 修法

1. 验收指标从**绝对夏普**换成**相对匹配基准的 alpha / IR**（见第 6 节，这不是形式问题，是功效问题）；
2. 单窗口只判「执行异常 + 灾难性亏损」：回撤超预算、成交率异常、无法退出；
3. 有效性只看拼接后的 4–6 年样本外曲线，附区块自助法置信区间；
4. 「2/3 窗口为正」降级为描述性统计，不作通过条件；
5. 明确记录试验次数，成熟后接 Deflated Sharpe / PBO。

## 6. alpha 没有定义：比统计更致命

方案 §12.4 的基准是宽基指数 + 简单动量 + 两策略互比。这不足以支撑「选股能力」的结论，因为 long-only A 股短线策略的收益绝大部分来自 **beta + 小市值 + 高波动**暴露。

缺失的两个基准：

- **同市值、同波动、同行业匹配的等权组合**——回答「是不是只是买了一篮子小盘高波动股」；
- **行业/板块中位数收益**——剥离行业轮动。

判断标准：若策略收益能被「小市值 + 高波动 + 近月涨停次数」等暴露解释掉，它就不是 alpha。这类收益在 2024 年初微盘股流动性危机、2026-07-06 ST 制度变更这类风格切换中会直接崩溃。

配套缺口：§7.4 模式 C 列了行业集中度，但没有**市值/风格暴露约束**，也没有暴露归因报告。

**这也是第 5 节功效问题的根源**：绝对收益的波动主要来自市场 beta；扣掉 beta 之后 alpha 波动小得多，IR 高于夏普，所需样本年限显著下降。用 beta 主导的指标做验收，既浪费统计功效，又测错了对象。

## 7. 存活偏差：原则有了，落地没有

方案 §1.2/§3.2 把「历史股票池」列为原则，但免费源能否重建「当时可交易、后来退市」的名单，是本项目最大的隐性成本。

| 来源 | 能拿到 | 不能确认 |
|---|---|---|
| BaoStock | 日线含 `isST`、`tradestatus`；`query_stock_basic` 有 `status`/`outDate`；1990-12 起；免费免注册 | 退市股历史 K 线能否稳定取到（需实测）；代码变更/暂停上市/重新上市/北交所迁移 |
| TuShare（2000 分档） | `stock_basic(list_status='D')` 退市名单、`suspend_d`、`stk_limit`、`adj_factor`、`index_member_all` | `stk_limit` 历史起始未标注（示例最早 2019）；`namechange` 积分要求未标注 |
| AkShare | 当前 ST/停牌池、巨潮逐股行业变更 | 无历史涨跌停价；依赖网页接口，稳定性差，宜作补数 |

**风险**：用当前股票列表拉历史日线，会系统性高估毛收益。方案 §3.3 的十条数据质量检查没有一条能发现这个问题——因为数据本身「正确」，只是样本不对。

建议增加一条检查：**回测股票池每日成分数量应与交易所历史上市公司数对账**，偏差超过阈值即告警。

## 8. 工程可行性与实施顺序

### 8.1 工作量（单人熟练 Python + 量化）

| 阶段 | 人周 |
|---|---|
| 数据层（含复权、状态、校验） | 3–5 |
| 策略层 + 条件诊断 | 1–2 |
| 回测引擎（撮合、T+1、涨跌停、费用） | 4–6 |
| 验证（切分、滚动、敏感性、统计） | 3–4 |
| 报告 | 1–2 |
| 模拟实盘观察 | 8–12 |

合计约 **3–4.5 个月开发 + 3 个月观察**。

### 8.2 框架参考

-**自研日线事件驱动引擎是合理选择**（通用框架难改撮合细则）。

| 框架 | 可借鉴 | 注意 |
|---|---|---|
| rqalpha | 涨跌停检查、停牌拒单、T+1 `sellable`、交易成本 mod、分红处理 | 首选参考 |
| qlib | `limit_threshold`、停牌（close 为空）处理 | 需自行配置 |
| vnpy | 撮合骨架 | **不适合**：期货/CTA 主战场，无 A 股涨跌停/停牌校验 |
| backtrader | 通用事件骨架 | A 股规则需全部自写 |

### 8.3 顺序建议：先做垂直切片

不要把阶段一到四依次做完再验证。先用 2 周做一条垂直切片：

> 数据（**含退市股样本**）→ 信号 → 次日开盘买入 → 固定持有 N 日 → 收益分布（**相对匹配基准**）

必须带三个保守过滤：**开盘涨停不买、停牌不买、成交额下限**。否则毛边际会被高估，而这正是切片唯一要回答的问题。

判据：**每笔毛超额 ≥ 0.6%，且置信区间下界 > 0.3%**（对应扣成本后仍有正期望）。达不到就不要建完整系统。

这与 §1.3「第一阶段只做日线」并不冲突，只是把验证提前。

## 9. 其他会影响成败、方案未覆盖的点

1. **盘中止损的可执行性被高估**。§7.1 用当日 high/low 触发止损/止盈，隐含「盘中盯盘或条件单」；多数券商条件单有延迟、部分不支持。建议把「收盘信号 → 次日开盘执行」设为主规则，盘中止损只作实验组，并在模拟实盘记录偏差。
2. **模拟实盘时长与样本不足**。8–12 周只有 40–60 笔。建议写明最低样本：≥80 笔且覆盖一次 ≥5% 的指数回撤。
3. **预注册缺失**。§4.4/§4.5 写「部分或全部」「可研究」，没有冻结一套主规则；参数搜索只说「有限」，没有试验次数预算；DSR/PBO 只在名词层面。建议阶段二结束时冻结**主规则 + 参数 + 试验次数上限**，写入 `strategy_definitions` 并加锁。
4. **风险预算无数值**。单票上限、总仓位、最大持仓数、行业集中度、最大回撤阈值全部空缺，§15 的「最大回撤符合事先设定的风险预算」因此不可复现。
5. **§9.1 示例区间已过期**。2016–2022 / 2023–2024 / 2025– 的划分，到 2026-10 样本外已积累 21 个月。若尚未运行，仍属干净样本外；若已查看，必须重新划界。且 2026-07-06 制度变更落在样本外期内，需单列。
6. **程序化交易报备**。2024-10-08 起《证券市场程序化交易管理规定（试行）》施行，程序化交易需经券商报告；日频策略不属高频，影响有限，但实盘前需确认流程。
7. **数据快照不可变**。方案有 `data_version` 但无内容哈希。建议每次回测对行情表做快照哈希，否则「相同数据复现相同结果」无法自证。
8. **策略 alpha 来源未分解**。该策略本质是短期动量延续，而 A 股周度尺度上反转效应常被报告。这不否定策略，但要求消融测试能区分「趋势溢价」「超跌反弹溢价」「涨停溢出」三类来源，否则无法判断收益来源是否可重复。

## 附录 B：数字复算方法

```python
from math import comb, sqrt   # 统计量
# 窗口 t 值
t = sr_annual / sqrt(252) * sqrt(n_days)
# "2/3 窗口为正" 双向概率（二项分布）
sum(comb(n, i) for i in range(k, n + 1)) / 2**n          # 零假设
sum(comb(n, i)*p**i*(1-p)**(n-i) for i in range(k, n+1))  # p=Φ(SR√(T/12))
# 单笔信噪比与所需笔数
mu = p_win*W - (1-p_win)*L; sd = sqrt(p*(W-mu)**2 + (1-p)*(L+mu)**2)
n_needed = (2 / (mu/sd))**2
# 每轮成本
buy  = comm + slip + transfer + fee + reg
sell = buy + stamp
round_trip = buy + sell
annual = round_trip * (250 / hold_days)
```

复算示例（当前口径）：`comm=0.00025, slip=0.001, transfer=0.00001, fee=0.0000341, reg=0.00002, stamp=0.0005`
→ 买入 0.1314%、卖出 0.1814%、双边 **0.3128%**、7 日持仓年化 **11.2%**（简单相加）。
